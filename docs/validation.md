The runtime tests start the actual bundled Worker in workerd/Miniflare with isolated KV and mocked upstream responses. The official Inspector CLI runs against a loopback HTTP listener in both protocol eras. It uses real OAuth-provider token encryption/validation, verifies unauthenticated access rejection and CIMD/S256 metadata, optionally registers a DCR client, and executes the smoke script. Temporary token files have private permissions and are removed afterward.

The second runtime test invokes Wrangler's `deploy --dry-run` against configuration generated by the same pure helper used by `setup:deploy`, using synthetic owner settings and namespace ID. This verifies the self-deployment configuration without creating a Worker/KV namespace or uploading secrets.

Security tests cover missing/invalid/altered/expired/revoked tokens, wrong audience, wrong subject, insufficient scopes, PKCE, consent CSRF/replay, invalid redirect URIs, configured browser origins and CORS preflight, Host validation, GitHub allowlisting, CIMD exchange, optional DCR, instance isolation, source ownership, secret redaction, missing configuration and body limits. Full simulated GitHub authorization succeeds for the allowlisted identity and fails for another identity.

API/domain tests cover documented Basic auth, exact paths/query serialization, range/array/body limits, timeouts during headers/body, total request budget, retries, Retry-After seconds/dates, redirect rejection, invalid schema/JSON, units, null/zero distinction, local dates, source fitness, computed form, calendar pairing, empty data and incomplete aggregations.

The base local development command was also started successfully and stopped after checking that unconfigured `/mcp` safely returns 503 with privacy headers. No `.dev.vars` containing live secrets was created.

The complete `pnpm audit` (including development dependencies) also reports no known vulnerabilities after the documented minimatch override. Function-spacing rules were checked with deliberately adjacent declarations, assigned functions and class methods: ESLint rejected them and its autofix inserted the required blank lines.

## Verification boundaries

The Node tests use a Workers base-class shim and a KV test double; native fetch/crypto/KV/metadata/MCP serving are independently checked in workerd. The automated Inspector fixture uses a test-only registered client. Separate tests exercise CIMD resolution and optional DCR. Those checks are not a live account authorization or client installation.

Each owner must independently verify:

- Real Intervals API connectivity, payloads and synchronization freshness with an owner's credentials.
- Real GitHub browser authorization/callback setup for an owner's OAuth app.
- Production deployment, actual public URL, remote metadata and authenticated requests.
- Live ChatGPT or another named client authorization, discovery and retrieval of real athlete data.

Production deployment remains a separate owner action. Maintainers should enable private vulnerability reporting, secret scanning where available and required CI for public releases. Follow [self-hosting](self-hosting.md) for owner setup and [client compatibility](clients.md) for connection requirements.

## Code review before publication

The review separated tool contracts from service orchestration, extracted calendar normalization and pairing, and split HTTP security policy, OAuth provider configuration, browser authorization and consent rendering into focused modules. Calendar assembly uses explicit date guards rather than non-null assertions; undated source events fail instead of disappearing from the result. Regression tests cover those cases and forbid implicit pairing by name/date. The README keeps the core workflow concise and uses Mermaid for architecture, with detailed operations in linked guides.

Function spacing is enforced through maintained ESLint Stylistic rules, with blank lines around declarations and assigned functions and between class methods. Targeted JSDoc explains date arithmetic, incomplete totals, source conversions, OAuth trust boundaries and upstream retry/deadline behavior.

The type-aware recommended ESLint preset, required braces, strict equality with nullish checks, and exhaustive-switch rule also pass across the repository. Deliberately invalid snippets confirmed rejection of missing braces, loose equality, an async function without asynchronous work, and an incomplete union switch. Only test doubles are exempt from `require-await`; production functions retain that check. GitHub identity verification separates token exchange, schema validation, identity lookup and the owner check with blank lines.

OAuth navigation regression tests exercise a synthetic native CIMD client with a variable loopback callback port. Foreign and opaque (`null`) Origins can reach the consent page without receiving CORS access. Valid consent handles/cookies cannot authorize a cross-site POST, forged callbacks fail, canonical-host checks remain enforced, and the same Origins are rejected at `/mcp`. These cases also pass against the production bundle in workerd.

A real Chrome check using synthetic loopback forms reproduced `Origin: null` under `no-referrer` and the correct same-origin Origin under `same-origin`. Regression assertions verify the consent page's `same-origin` policy, default `no-referrer` on redirects/errors, and CSP targets limited to self, GitHub and the validated client redirect origin. This browser check does not authorize a real client or establish a completed owner sign-in.
