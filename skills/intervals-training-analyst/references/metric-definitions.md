# Metric definitions and limitations

Source names below are the Intervals fields mapped by this server, not fields to query directly. The [tool mapping](mcp-tool-mapping.md) is the invocation contract. Metric availability does not establish measurement accuracy or physiological meaning.

| Metric                      | Definition and unit                                                                        | Source → normalized field                                                                                                     | Interpretation and common misuse                                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fitness / CTL               | Intervals' calculated longer-term training-load history, source load units                 | Wellness `ctl` → `fitness_ctl`                                                                                                | Compare within this athlete's source configuration. Not VO2max, race ability or directly measured fitness. This tool does not expose CTL time constants; do not assume them or reconstruct CTL.                                                              |
| Fatigue / ATL               | Intervals' calculated shorter-term training-load history, source load units                | Wellness `atl` → `fatigue_atl`                                                                                                | Describes modeled load, not a direct measurement of tiredness, recovery or illness. Do not reconstruct it or assume a fixed time constant.                                                                                                                   |
| Form / TSB                  | No daily source TSB is exposed. Server derives same-day CTL minus ATL in source load units | `source_form_tsb` always null; `computed_form.value`, `origin`, `formula`, `unit`                                             | Label **computed form**, not source TSB. Negative is a modeled relationship, not overtraining. Profile `form_as_percent` is a display setting, not a conversion; this is neither percentage form nor previous-day TSB.                                       |
| Activity training load      | Source load assigned to a session; source-defined units                                    | Activity `icu_training_load` → `training_load`; interval `training_load` → `training_load`                                    | Do not rename it TSS, infer its method, or compare unlike sport/device methods as identical. Daily `ctlLoad` and `atlLoad` remain separate `source_values`, not a generic daily total. `rampRate` stays source-defined; do not label it a new agent formula. |
| Distance and elevation      | Recorded distance and elevation gain, meters                                               | `distance` → `distance_m`; `total_elevation_gain` → `elevation_gain_m`                                                        | Convert meters/1000 to km for display. GPS/elevation errors and hills affect comparisons. Gain alone does not establish terrain, gradient distribution or altitude.                                                                                          |
| Duration                    | Moving versus elapsed seconds                                                              | `moving_time` → `moving_time_s`; `elapsed_time` → `elapsed_time_s`                                                            | Preserve the distinction, especially for paused runs/intervals. Calendar actual duration is moving time. Neither proves continuous steady running.                                                                                                           |
| Speed and pace              | Average source speed in m/s; derived pace in seconds/km                                    | `average_speed` → `average_speed_mps`, `average_pace_s_per_km = 1000 / speed`                                                 | Lower pace is faster; higher speed is faster. Format seconds as mm:ss/km at the end, not before calculation. Source average speed need not exactly equal distance/moving time. Null/nonpositive speed gives no pace. Max speed is not sustainable pace.      |
| Heart rate                  | Average/max recorded HR, bpm                                                               | `average_heartrate`, `max_heartrate` → `average_heart_rate_bpm`, `max_heart_rate_bpm`                                         | HR varies with intensity and context; a session average cannot show within-run drift. Optical artifacts and different sensors can confound comparisons. Do not infer zones without valid sport-specific settings.                                            |
| Threshold settings          | Configured sport-specific FTP watts, LTHR bpm, max HR bpm and threshold speed m/s          | Profile `sportSettings`: `ftp`, `lthr`, `max_hr`, `threshold_pace` → `ftp_w`, `lthr_bpm`, `max_hr_bpm`, `threshold_speed_mps` | Match `types` to the sport. Despite its source name, `threshold_pace` is speed, not min/km. Settings are not a fresh threshold test or proof of session intensity. A workout called threshold does not validate the setting.                                 |
| Power                       | Source average watts                                                                       | Activity `icu_average_watts` / interval `average_watts` → `average_power_w`                                                   | Missing power is normal. Device/algorithm changes affect comparability; running power is not interchangeable across systems. No device provenance or power stream is exposed.                                                                                |
| Cadence                     | Source revolutions/min; running steps/min derived by server                                | `average_cadence` → `average_cadence_source_rpm`, running `average_cadence_spm = 2 × rpm`                                     | Use spm as returned; do not double it again. No universal ideal cadence or injury conclusion follows. Non-running cadence retains rpm.                                                                                                                       |
| Resting HR                  | Source resting HR in bpm                                                                   | Wellness `restingHR` → `resting_heart_rate_bpm`                                                                               | Compare to the athlete's recorded baseline with coverage/method caveats. Missing does not mean normal; an increase does not diagnose illness or fatigue.                                                                                                     |
| HRV                         | Source HRV and SDNN values; method/units not guaranteed by this contract                   | `hrv`, `hrvSDNN` → `hrv_source`, `hrv_sdnn_source`                                                                            | Do not assume RMSSD/ms, merge methods, or apply population thresholds. Compare only known-consistent measurements. Nulls remain missing.                                                                                                                     |
| Sleep                       | Recorded sleep seconds and source scores                                                   | `sleepSecs`, `sleepScore`, `sleepQuality` → `sleep_duration_s`, `sleep_score`, `sleep_quality`                                | Convert seconds/3600 for hours. Scores have source-defined scales; wearable estimates are context, not a diagnosis of sleep quality.                                                                                                                         |
| Subjective/recovery context | Fatigue, soreness, stress, mood, motivation, readiness in source scales                    | Same source names → same normalized names                                                                                     | Preserve scales without guessing direction, range or clinical thresholds. A readiness score is not permission to train/race. Missing days are not zero.                                                                                                      |
| Other wellness              | Weight kg, SpO2 percent, steps count                                                       | `weight`, `spO2`, `steps` → `weight_kg`, `spo2_percent`, `steps`                                                              | Report only when relevant; avoid clinical interpretation or body-composition claims. Profile weight and daily wellness weight can differ in date/source.                                                                                                     |

## Analytics additions

| Metric                     | Origin, unit and rule                                                    | Limitation                                                                                                                                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `computed_same_day_form`   | Computed from dated Wellness `ctl - atl`, source load units              | Same-day convention only; not source TSB. Legacy `computed_form` remains unchanged.                                                                                                                                                      |
| `source_efficiency_factor` | Source Activity `icu_efficiency_factor`, source-defined units            | Current OpenAPI confirms a number but does not define its calculation basis. Historical maintainer material describes normalized power/HR and discusses running alternatives. Do not assume average speed/HR or compare different bases. |
| `source_decoupling`        | Source Activity `decoupling`, source-defined convention                  | Not reconstructed; API schema does not establish units/sign/calculation for each sport. Missing is null, not zero drift.                                                                                                                 |
| `speed_hr_proxy`           | Computed `average_speed_mps / average_heart_rate_bpm`, `(m/s)/bpm`       | Running-only selected steady-aerobic sessions; observational proxy, not directly measured running economy.                                                                                                                               |
| Period totals              | Computed sums of source distance m, moving/elapsed s and load separately | Null total when structural or metric coverage fails; `known_sum` is partial, never a complete total. Scope is returned records.                                                                                                          |
| Weekly-normalized volume   | Computed total × 7 / inclusive days, m/week or s/week                    | Descriptive exposure normalization; no prediction for uncompleted days.                                                                                                                                                                  |
| Pooled moving pace         | Computed `1000 * sum moving seconds / sum distance meters`, s/km         | Complete positive inputs required; distinct from individual source speed-derived pace.                                                                                                                                                   |

Analytics `provenance` identifies source field or calculation and units; `method_version` identifies the numerical contract. Preserve it alongside dates, sample size and `data_quality`. Source subtype `RACE` and known `trainer` flags can constrain comparisons; unknown flags and VirtualRun alone do not establish a treadmill/outdoor setting. The API does not reliably classify easy/threshold/interval purpose from a name.

## Verified sources

Field semantics are grounded in the repository's normalizers, schemas and validated fixtures, plus the [Intervals OpenAPI](https://intervals.icu/api/v1/docs), [maintainer API guide](https://forum.intervals.icu/t/api-access-to-intervals-icu/609), [fitness-in-wellness clarification](https://forum.intervals.icu/t/ios-app-fitnessfatigue-for-intervals-icu-data/11186) and [running cadence clarification](https://forum.intervals.icu/t/additional-or-different-units/4526). These links are provenance for maintainers, not required external calls during an athlete review. The schema does not resolve HRV/subjective-score semantics; report that uncertainty instead of adding assumptions.
